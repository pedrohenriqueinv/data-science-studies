What is a Version Control System (VCS) and its primary purpose in Data Engineering?	"<b>English:</b> A software system that records and audits changes to files over time, enabling teams to track authorship, compare revisions, rollback bugs, and maintain reproducibility in data pipelines.<br><br><b>Portuguese:</b> Um sistema de software que gerencia e audita o histórico de alterações em arquivos, permitindo rastrear autoria, comparar versões, reverter erros e manter reprodutibilidade em pipelines de dados."
Where does Git store all internal objects, configuration, and commit history?	"<b>English:</b> In the hidden <code>.git/</code> directory located at the root of the repository. Deleting this folder completely removes version tracking.<br><br><b>Portuguese:</b> No diretório oculto <code>.git/</code> na raiz do projeto. Deletar esta pasta apaga todo o histórico e metadados de versionamento."
What is a Git Blob object?	"<b>English:</b> A Binary Large Object storing the compressed raw content of a file, completely independent of its filename, timestamps, or directory path.<br><br><b>Portuguese:</b> Um objeto binário que armazena o conteúdo puro e comprimido de um arquivo, desvinculado de nome, datas ou caminhos de diretório."
What is a Git Tree object?	"<b>English:</b> An object representing a directory state, mapping file permissions and names to their corresponding Blob or child Tree SHA-1 hashes.<br><br><b>Portuguese:</b> Um objeto que representa a estrutura de um diretório, mapeando nomes de arquivos e permissões aos hashes SHA-1 de Blobs ou sub-Trees correspondentes."
What is a Git Commit object?	"<b>English:</b> An immutable node pointing to a root Tree object, containing author and committer metadata, timestamps, a commit message, and parent commit hashes.<br><br><b>Portuguese:</b> Um nó imutável que aponta para uma Tree raiz, contendo metadados de autor/committer, data/hora, mensagem descritiva e os hashes dos commits pais."
How does Git save disk space through deduplication across commits?	"<b>English:</b> When a file is unmodified between commits, the new Tree object simply points to the existing Blob hash in the object database rather than storing a new copy.<br><br><b>Portuguese:</b> Quando um arquivo não muda entre commits, a nova Tree apenas reutiliza o ponteiro para o hash do Blob pré-existente no banco de dados, sem duplicar dados."
What cryptographic hash algorithm does Git traditionally use to generate 40-character IDs?	"<b>English:</b> SHA-1 (Secure Hash Algorithm 1). In modern Git versions, SHA-256 is also supported for enhanced collision resistance.<br><br><b>Portuguese:</b> SHA-1 (Secure Hash Algorithm 1). Versões modernas do Git também oferecem suporte experimental ao SHA-256 para maior segurança criptográfica."
What is the difference between git diff and git diff --staged?	"<b>English:</b> <code>git diff</code> inspects modifications in the Working Tree against the Staging Area (unstaged changes), while <code>git diff --staged</code> compares the Staging Area against the latest commit (staged changes).<br><br><b>Portuguese:</b> <code>git diff</code> compara alterações na pasta de trabalho contra a Staging Area (modificações não preparadas), enquanto <code>git diff --staged</code> compara a Staging Area contra o último commit (modificações preparadas)."
How do you remove a staged file without destroying its edits in the working directory?	"<b>English:</b> Run <code>git restore --staged <file></code> (or <code>git reset HEAD <file></code>).<br><br><b>Portuguese:</b> Executa-se <code>git restore --staged <arquivo></code> (ou <code>git reset HEAD <arquivo></code>)."
Why is git revert preferred over git reset on shared branches?	"<b>English:</b> <code>git revert</code> creates a new forward-moving commit that applies the inverse diff, preserving complete audit history and avoiding desynchronization with remote teammates.<br><br><b>Portuguese:</b> <code>git revert</code> cria um novo commit que inverte as mudanças do commit alvo, preservando o histórico de auditoria intacto e evitando quebra de sincronia com a equipe."
