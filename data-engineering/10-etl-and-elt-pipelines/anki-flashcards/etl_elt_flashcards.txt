What is the architectural difference between ETL and ELT in modern data engineering?	"<b>English:</b> In ETL, data is transformed in an intermediate processing layer before loading into the destination. In ELT, raw data is loaded directly into the destination storage/lake, and transformations are performed in-warehouse using cloud compute engines.<br><br><b>Portuguese:</b> No ETL, as transformações ocorrem em um servidor intermediário antes do carregamento. No ELT, os dados brutos são carregados diretamente no destino (Data Lake/Warehouse) e transformados usando o poder computacional distribuído da própria nuvem."
Why is Apache Parquet significantly faster and cheaper than CSV for cloud analytics?	"<b>English:</b> Parquet is a columnar binary format with snappy compression. It enables column pruning (reading only requested columns) and predicate pushdown (skipping irrelevant row groups via embedded min/max stats), drastically cutting I/O costs.<br><br><b>Portuguese:</b> Formato colunar binário com compressão eficiente. Permite ler apenas as colunas necessárias e descartar blocos de linhas irrelevantes via estatísticas min/max embutidas, reduzindo drasticamente custos de I/O."
What does 'idempotency' mean when designing data ingestion pipelines?	"<b>English:</b> A property where running the pipeline multiple times with the same input produces the exact same end state without creating duplicate records or data corruption.<br><br><b>Portuguese:</b> Propriedade na qual executar o pipeline repetidas vezes com os mesmos dados de entrada produz o mesmo estado final exato, sem gerar duplicatas ou corrupção."
What is the purpose of partition pruning when querying partitioned Parquet datasets?	"<b>English:</b> It instructs the query engine to completely bypass reading folder directories that do not match query filter predicates (e.g., skipping all years except 2026).<br><br><b>Portuguese:</b> Permite ao motor de consulta ignorar totalmente a leitura de diretórios/pastas que não satisfazem o filtro da query (ex: pulando anos diferentes de 2026)."
What is an 'upsert' operation in database engineering?	"<b>English:</b> A hybrid operation combining UPDATE and INSERT: it updates an existing record if its unique key matches, or inserts a new row if no match exists.<br><br><b>Portuguese:</b> Operação híbrida que atualiza o registro caso a chave primária já exista, ou insere uma nova linha caso o registro seja inédito."
