What is the difference between Data (Raw Element) and Information (Processed Data) in database theory?	"<b>English:</b><br>• <i>Data:</i> Isolated, raw, and uncontextualized facts (e.g., '25', 'Aline', 'True').<br>• <i>Information:</i> Organized, contextualized data useful for decision-making (e.g., 'Student Aline borrowed book ID 25 on 02/09/2026').<br>• <i>Analogy:</i> Flour/sugar in the pantry is Data; the decorated birthday cake is Information.<br><br><b>Portuguese:</b><br>• <i>Dado:</i> Elemento cru, isolado e sem contexto (ex: '25', 'Aline', 'True').<br>• <i>Informação:</i> Dado processado, contextualizado e útil para decisão (ex: 'A aluna Aline retirou o livro ID 25 em 02/09/2026').<br>• <i>Analogia:</i> Farinha e açúcar no armário são Dados; o bolo pronto de aniversário é a Informação."
What is a DBMS (SGBD) and what are its four fundamental functions?	"<b>English:</b> A Database Management System (DBMS) is software that mediates all operations between users/applications and physical disk files.<br>• <i>4 Functions:</i> 1. Structure definition (DDL), 2. Data manipulation and querying (DML/DQL), 3. Security and access control (DCL), 4. Integrity and crash recovery (WAL/Backups).<br><br><b>Portuguese:</b> Um Sistema Gerenciador de Banco de Dados (SGBD) é o software intermediário entre usuários/aplicações e os arquivos no disco.<br>• <i>4 Funções:</i> 1. Criação e definição de estruturas (DDL), 2. Manipulação e consulta (DML/DQL), 3. Controle de acesso e segurança (DCL), 4. Integridade e recuperação de falhas (WAL/Backups)."
How did database models evolve historically from the 1960s to modern architectures?	"<b>English:</b><br>• <i>Hierarchical (1960s - IBM IMS):</i> Rigid tree structure (single parent per child).<br>• <i>Network (1970s - CODASYL):</i> Graph structure (multiple parents allowed), but complex pointer-based navigation.<br>• <i>Relational (1980s - Edgar Codd):</i> 2D tables (relations) connected by keys with declarative SQL.<br>• <i>Object-Oriented (1990s):</i> Stored classes/objects natively, but lacked universal market standards.<br>• <i>NoSQL (2000s+):</i> Flexible schema, horizontal scalability (Documents, Key-Value, Graphs, Columnar).<br><br><b>Portuguese:</b><br>• <i>Hierárquico (1960 - IBM IMS):</i> Árvore rígida (um único pai por filho).<br>• <i>Em Rede (1970 - CODASYL):</i> Grafo (múltiplos pais), navegação complexa por ponteiros.<br>• <i>Relacional (1980 - Edgar Codd):</i> Tabelas bidimensionais ligadas por chaves e SQL declarativo.<br>• <i>Orientado a Objetos (1990):</i> Classes e herança nativa, baixa padronização no mercado.<br>• <i>NoSQL (2000+):</i> Esquema flexível e escalabilidade horizontal (Documentos, Chave-Valor, Grafos, Colunares)."
What are the four ACID properties that guarantee transaction reliability in relational databases?	"<b>English:</b><br>• <b>A - Atomicity:</b> 'All or nothing'. If one step fails, the entire transaction is rolled back.<br>• <b>C - Consistency:</b> The database transitions from one valid state to another, strictly enforcing constraints (PK, FK, CHECK).<br>• <b>I - Isolation:</b> Concurrent transactions execute without interfering with one another.<br>• <b>D - Durability:</b> Once committed, changes survive server crashes and power failures via the Write-Ahead Log (WAL).<br><br><b>Portuguese:</b><br>• <b>A - Atomicidade:</b> 'Tudo ou nada'. Se uma etapa falhar, ocorre ROLLBACK total.<br>• <b>C - Consistência:</b> O banco transita de um estado válido para outro, respeitando constraints (PK, FK, CHECK).<br>• <b>I - Isolamento:</b> Transações simultâneas não interferem entre si.<br>• <b>D - Durabilidade:</b> Após o COMMIT, os dados sobrevivem a quedas de energia e falhas de hardware (gravados no WAL)."
What are the four ANSI SQL transaction isolation levels and their concurrency vulnerabilities?	"<b>English:</b><br>1. <i>Read Uncommitted:</i> Vulnerable to Dirty, Non-Repeatable, and Phantom reads.<br>2. <i>Read Committed (Default in PostgreSQL/Oracle):</i> Prevents Dirty reads; vulnerable to Non-Repeatable and Phantom reads.<br>3. <i>Repeatable Read:</i> Prevents Dirty and Non-Repeatable reads; may suffer Phantom reads in some engines.<br>4. <i>Serializable:</i> Fully prevents all anomalies by simulating strict sequential queue execution.<br><br><b>Portuguese:</b><br>1. <i>Read Uncommitted:</i> Sujeito a Leitura Suja, Não-Repetível e Fantasma.<br>2. <i>Read Committed (Padrão PostgreSQL/Oracle):</i> Protegido contra Leitura Suja; sujeito a Não-Repetível e Fantasma.<br>3. <i>Repeatable Read:</i> Protegido contra Leitura Suja e Não-Repetível; sujeito a Fantasma em alguns SGBDs.<br>4. <i>Serializable:</i> Isolamento total contra todas as anomalias (execução em fila estrita)."
What are the core internal components of a relational DBMS?	"<b>English:</b><br>• <i>Execution Engine:</i> Executes physical query operators.<br>• <i>Planner/Query Optimizer:</i> Determines the lowest-cost execution plan (Index scan vs. Seq scan).<br>• <i>Buffer Manager (Buffer Pool):</i> Caches disk pages in RAM to reduce costly disk I/O.<br>• <i>Storage Manager:</i> Allocates data blocks and table files on disk.<br>• <i>Concurrency Manager:</i> Manages locks and MVCC (Multi-Version Concurrency Control).<br>• <i>Recovery Manager:</i> Uses WAL logs to perform REDO or UNDO operations.<br><br><b>Portuguese:</b><br>• <i>Motor de Execução:</i> Executa os passos do plano físico.<br>• <i>Otimizador de Consultas:</i> Escolhe o caminho mais veloz (índice B-Tree vs varredura sequencial).<br>• <i>Gerenciador de Buffer (Buffer Pool):</i> Mantém páginas em memória RAM para evitar I/O em disco.<br>• <i>Gerenciador de Armazenamento:</i> Aloca blocos e arquivos no HDD/SSD.<br>• <i>Gerenciador de Concorrência:</i> Gerencia travas (Locks) e versões de linhas (MVCC).<br>• <i>Gerenciador de Recuperação:</i> Garante durabilidade usando WAL para REDO e UNDO."
What are the five structural subgroups of the SQL language and their primary commands?	"<b>English:</b><br>• <b>DDL (Data Definition):</b> CREATE, ALTER, DROP, TRUNCATE, RENAME.<br>• <b>DML (Data Manipulation):</b> INSERT, UPDATE, DELETE, MERGE.<br>• <b>DQL (Data Query):</b> SELECT.<br>• <b>DCL (Data Control):</b> GRANT, REVOKE, DENY.<br>• <b>TCL (Transaction Control):</b> BEGIN, COMMIT, ROLLBACK, SAVEPOINT.<br><br><b>Portuguese:</b><br>• <b>DDL (Definição de Estrutura):</b> CREATE, ALTER, DROP, TRUNCATE, RENAME.<br>• <b>DML (Manipulação de Dados):</b> INSERT, UPDATE, DELETE, MERGE.<br>• <b>DQL (Consulta de Dados):</b> SELECT.<br>• <b>DCL (Controle de Acesso):</b> GRANT, REVOKE, DENY.<br>• <b>TCL (Controle Transacional):</b> BEGIN, COMMIT, ROLLBACK, SAVEPOINT."
What is the critical exam difference between DROP, TRUNCATE, and DELETE?	"<b>English:</b><br>• <i>DELETE (DML):</i> Deletes row-by-row, logs each row in the transaction log, and can be rolled back.<br>• <i>TRUNCATE (DDL):</i> Instantly deallocates all table data pages, resets auto-increment PK sequences, and alters table structure.<br>• <i>DROP (DDL):</i> Completely destroys the entire table, its structure, schema definition, indexes, and data.<br><br><b>Portuguese:</b><br>• <i>DELETE (DML):</i> Apaga linha a linha, registra no log transacional e aceita ROLLBACK.<br>• <i>TRUNCATE (DDL):</i> Desaloca blocos de páginas no disco instantaneamente e reseta a sequência de auto-incremento (ID).<br>• <i>DROP (DDL):</i> Destrói a tabela por completo (estrutura, colunas, dados e índices deixam de existir)."
What are the fundamental rules governing a Primary Key (PK) vs. Foreign Key (FK)?	"<b>English:</b><br>• <i>Primary Key (PK):</i> Uniquely identifies each row in a table. It is strictly UNIQUE and NOT NULL. A B-Tree index is automatically generated.<br>• <i>Foreign Key (FK):</i> References the PK of another table to maintain referential integrity and avoid orphan rows.<br><br><b>Portuguese:</b><br>• <i>Chave Primária (PK):</i> Identifica exclusivamente cada linha. É obrigatoriamente ÚNICA e NOT NULL (nunca aceita nulos). Gera índice B-Tree automático.<br>• <i>Chave Estrangeira (FK):</i> Referencia a PK de outra tabela, garantindo que não existam registros órfãos."
What are the referential actions for Foreign Keys: RESTRICT vs. CASCADE vs. SET NULL?	"<b>English:</b><br>• <i>RESTRICT / NO ACTION (Default):</i> Blocks the update/delete on the parent if child rows exist.<br>• <i>CASCADE:</i> Propagates parent deletion/update automatically to all dependent child rows.<br>• <i>SET NULL:</i> Keeps the child rows but sets the foreign key column to NULL.<br><br><b>Portuguese:</b><br>• <i>RESTRICT / NO ACTION (Padrão):</i> Bloqueia a exclusão/alteração no pai enquanto houver filhos dependentes.<br>• <i>CASCADE:</i> Propaga em cascata: apagar o pai apaga automaticamente todos os filhos vinculados.<br>• <i>SET NULL:</i> Mantém os registros filhos, preenchendo a FK com NULL."
What is the mandatory order of Insertion and Deletion between Parent and Child tables when using RESTRICT?	"<b>English:</b><br>• <i>Insertion:</i> Always insert the Parent table first (e.g., authors), then the Child table (e.g., books).<br>• <i>Deletion:</i> Always delete Child records first, and only then delete the Parent record!<br><br><b>Portuguese:</b><br>• <i>Inserção:</i> Insere primeiro na tabela Pai (autores) e depois no Filho (livros).<br>• <i>Exclusão com RESTRICT:</i> Exclui primeiro os registros Filhos (livros) e só depois o registro Pai (autores)!"
What happens if you run an UPDATE or DELETE without a WHERE clause in SQL?	"<b>English:</b> It does NOT produce a syntax error! The DBMS will successfully update or delete 100% of all rows across the entire table. In production, always filter by Primary Key.<br><br><b>Portuguese:</b> NÃO gera erro de sintaxe! O SGBD executará a alteração ou exclusão em 100% de todas as linhas da tabela. Em produção, sempre filtre pela Chave Primária."
What is the purpose of the PostgreSQL RETURNING clause in an INSERT statement?	"<b>English:</b> It immediately returns newly generated values (such as SERIAL auto-incremented primary keys) in the same network round-trip, avoiding a separate SELECT query.<br><br><b>Portuguese:</b> Permite retornar imediatamente dados gerados no INSERT (como IDs do SERIAL) na mesma viagem de rede (round-trip), sem precisar de um SELECT separado."
How do SAVEPOINT and ROLLBACK TO SAVEPOINT work inside an active SQL transaction?	"<b>English:</b> A SAVEPOINT creates an intermediate checkpoint inside a transaction. If a subsequent command errors out, you can run 'ROLLBACK TO SAVEPOINT name;' to undo only that faulty command without aborting the entire transaction.<br><br><b>Portuguese:</b> Um SAVEPOINT cria um marcador intermediário na transação. Se um comando posterior der erro, você pode rodar 'ROLLBACK TO SAVEPOINT nome;' para desfazer apenas o erro mantendo as operações válidas anteriores."
Why is SQLite architecturally distinct from PostgreSQL, MySQL, SQL Server, and Oracle?	"<b>English:</b> SQLite is Serverless and Embedded! It does not run as a standalone network daemon/service on TCP ports. The client application reads and writes directly to a single .db file on disk.<br><br><b>Portuguese:</b> O SQLite é Serverless (Sem Servidor) e Embarcado! Ele não roda como um serviço de rede escutando portas TCP. A própria aplicação lê e grava diretamente em um único arquivo .db no disco."
